# Architecture

## Overview

This project implements an event-driven serverless solution that automatically applies predefined tags to newly launched Amazon EC2 instances.

Amazon EventBridge listens for EC2 instance launch events generated by AWS CloudTrail and invokes an AWS Lambda function. The Lambda function extracts the newly created EC2 instance ID and applies the predefined tags using the Amazon EC2 API.

---

## Components

### Amazon EC2

Launches new EC2 instances that require automatic tagging.

---

### AWS CloudTrail

Records the EC2 `RunInstances` API call and forwards the event to Amazon EventBridge.

---

### Amazon EventBridge

Monitors CloudTrail events and triggers the Lambda function whenever a new EC2 instance is launched.

Event Pattern:

```
source: aws.ec2
detail-type: AWS API Call via CloudTrail
eventSource: ec2.amazonaws.com
eventName: RunInstances
```

---

### AWS Lambda

Processes the EventBridge event.

Responsibilities:

- Extract EC2 Instance ID
- Apply default tags
- Log execution status
- Handle exceptions

---

### Amazon CloudWatch

Stores Lambda execution logs for monitoring and troubleshooting.

---

### IAM

#### Lambda Execution Role

Permissions:

- ec2:CreateTags
- CloudWatch Logs

#### EventBridge Permission

Allows EventBridge to invoke the Lambda function.

---

### GitHub Actions

Automates Lambda deployment whenever code is pushed to the main branch.

Workflow:

```
Developer
     │
     ▼
GitHub Repository
     │
     ▼
GitHub Actions
     │
     ▼
AWS Lambda
```

---

## Complete Event Flow

```
Developer
     │
     ▼
GitHub Repository
     │
     ▼
GitHub Actions
     │
     ▼
AWS Lambda Deployment

-------------------------------------

EC2 Instance Launch
        │
        ▼
AWS CloudTrail
        │
        ▼
Amazon EventBridge
        │
        ▼
AWS Lambda
        │
        ▼
EC2 CreateTags API
        │
        ▼
Tagged EC2 Instance
        │
        ▼
Amazon CloudWatch Logs
```

## Benefits

- Fully serverless
- Event-driven automation
- Automatic governance through tagging
- Low operational overhead
- Continuous deployment using GitHub Actions
- Easily extensible for additional tagging rules
